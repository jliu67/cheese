# Leakage and bias audit

| Risk | Control | Automated evidence | Residual limitation |
|---|---|---|---|
| Look-ahead features | Only trailing shifts/rolls; future-mutation causality audit | `test_future_mutation_does_not_change_past_features` | Provider timestamps still require human verification |
| Same-close execution | One-session lag; first earned return starts after next-close execution | Target and decision-return tests | Next-close fills are still a simplifying assumption |
| Overlapping labels | Train label end must be strictly before test start | Splitter integrity tests | Overlap also reduces effective sample size |
| Random time split | No random splitter exists; annual expanding folds only | Splitter tests | Historical nonstationarity remains |
| Scaling/imputation leakage | Scikit-learn pipelines fit transforms inside each training fold | Model smoke/integration tests | Median imputation may not be optimal |
| Hyperparameter contamination | Tiny grids selected only in inner prequential folds | Parameters and fold dates are saved | Development selection still consumes outer OOS evidence |
| Probability-calibration leakage | Calibrator uses prequential predictions; evaluation uses later chronological tail | Calibration artifacts/tests of model path | Small samples can make calibration noisy |
| Macro release look-ahead | Explicit observation, release, vintage start/end replay | PIT visibility and conflict tests | Source release calendars must be correctly encoded |
| Macro revisions | Vintage schema; no current-vintage fallback | PIT data validation | Some providers may not offer complete vintages |
| Future filling | PIT replay selects only effective rows; no backward fill | PIT audit compares dates | Market providers may have undocumented corrections |
| Proxy-series mislabeling | Explicit history kind; proxy/synthetic cannot authorize claim | Provenance tests | Official-index methodology can still differ from ETF tracking |
| ETF inception leakage | Segment dates and KMLM live-ETF holdout requirement | Holdout provenance validation | Inception date itself does not guarantee clean adjusted data |
| Dividend errors | Input contract requires total-return levels | Positivity/completeness checks | Engine cannot infer whether a provider truly adjusted correctly |
| Stitch discontinuity | Pre-stitch requirement; long gaps and >30% daily jumps are fatal | Market loader tests | Smaller bad splices require source reconciliation |
| Survivorship bias | Only the user-mandated two current assets are investable; history identity is explicit | Provenance manifest | The ex-post choice of KMLM remains a research-selection fact |
| Final-test contamination | Development truncates before feature/target construction; hash freeze; one-time marker | Full integration test | Filesystem controls cannot prevent a person from copying data externally |
| Multiple testing | Candidate ledger, all candidate returns, block Reality Check, bootstrap | Determinism tests | Unlogged human ideas cannot be corrected statistically |
| Allocation selection bias | Outer predictions retained; final holdout selects nothing | Frozen manifest and integration path | Pre-holdout performance is not a final unbiased estimate |
| Transaction-cost omission | Costs charged from starting 100% VOO on one-way turnover | Cost-reduces-wealth test | Actual spreads/impact vary through time |
| False defensive timing | Explicit false-signal/opportunity-cost table | Full integration artifact | Daily attribution is approximate, not causal |

## Holdout integrity audit

The final evaluator performs validation and hash checks before reserving the holdout.
Immediately before any holdout feature, target, forecast, or metric is computed, it writes
the one-time marker. The integration test verifies freeze, first evaluation, refusal of a
second evaluation, failed gate, and VOO-only live allocation.

## Multiple-testing interpretation

The testing ledger counts feature variants, forecast horizons, four model families,
hyperparameter candidates, and allocator candidates generated by the program. White's
Reality Check is applied to all portfolio candidates retained in the run. The code calls it
a practical block-bootstrap Reality Check rather than overstating it as a full SPA
implementation.

Research ideas tried outside the program must be added to an external ledger. No software
can adjust for undisclosed specifications or for repeatedly redesigning the project after
observing the same historical sample.

## Known sources of irreducible uncertainty

- KMLM's live ETF record is short, and earlier index eras are not identical live fund
  histories.
- Forecast horizons overlap, so even purged inference has fewer independent observations
  than the row count suggests.
- Index and adjusted-close data can be corrected retroactively by providers.
- Slippage and spreads may widen during precisely the stress periods when rotation matters.
- Structural breaks can invalidate calibrated probabilities and historical relationships.
- The chosen two-asset universe and 2020 holdout boundary were specified with hindsight.

These limitations must remain visible even if the final result is positive.
